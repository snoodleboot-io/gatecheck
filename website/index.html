Why gatecheck?

Pre-commit actions should be fast, reproducible, and monorepo-aware. gatecheck is built for the way modern teams ship — PyPI-native package sources, a dependency-aware DAG runner, and a Rust core that gets out of your way.

📦

Real package sources

Install hooks from PyPI (public or private), git refs, local paths, or Docker images. No more GitHub-URL-only requirement.

🏢

Monorepo native

Workspace-aware config with per-package overrides, dependency graphs, and --affected execution that only runs what changed.

⚡

Rust-powered runner

DAG execution, parallel subprocess management, and file hashing implemented in Rust. Sub-10ms startup on a no-op commit.

🔒

Lockfile reproducibility

check.lock pins every resolved dependency with content hashes. gatecheck sync installs exactly what's locked.

🧩

Composable groups

Named groups with explicit parallelism, ordering, and git event bindings. gatecheck run lint just works.

🔍

Transparent cache

gatecheck cache why black tells you exactly why a rebuild was triggered. No more debugging opaque invalidations.

🌿

Project venv reuse

from = "project" runs hooks inside your existing venv — no shadow copies, no version drift, no duplicate installs.

🔀

Rich conditionals

Run hooks only on certain branches, when env vars are set, on CI, or when specific file patterns are staged.

One config to rule them

A single check.toml at the root of your repo. No YAML, no GitHub URLs, no shadow copies of your tools. 

[sources]
default-registry = "https://pypi.org/simple"

[[hook]]
id    = "ruff"
from  = "pypi:ruff>=0.4"
run   = "ruff check --fix {files}"
files = "*.py"

[[hook]]
id         = "mypy"
from       = "project"
run        = "mypy src/"
pass-files = false
when       = { env-not = "SKIP_MYPY" }

[group.lint]
hooks    = ["ruff", "mypy"]
parallel = true
on-event = "commit"
